# Asset Agent 代码阅读地图

本文对应协议 2.0 可扩展扫描器内核。2026-08-12 的固定模块、单文件 Snapshot 与 `socket` 模块实现已经归档，不再是当前代码路径。

## 1. 总体调用链

```text
cmd/asset-agent
  → cli.Run（从 Runtime.Modules 动态识别命令）
  → agent.Scanner（依赖计划、超时、panic 和失败隔离）
  → module.Registry（动态注册与确定性拓扑排序）
  → modules/<name>（平台无关业务模块）
  → provider 强类型能力接口
  → provider/linux（绑定现有 Linux 只读采集器）
  → collect/* + platform.Root
  → model.Batch / ModuleResult / AssetRecord / RelationshipRecord
  → report.WriteBatch（JSONL、manifest、sync、原子 rename）
```

调用方向保持单向。业务模块只依赖 Provider 接口和公共模型，不导入 Linux 实现；报告层只处理统一模型，不知道采集命令。

## 2. 建议阅读顺序

1. `internal/model/batch.go`：先理解协议 2.0 的批次、模块状态、资产、关系、证据和 manifest；
2. `internal/provider/provider.go`、`contracts.go`：理解动态能力集合和强类型契约；
3. `internal/module/module.go`、`registry.go`：理解模块描述符、注册和依赖计划；
4. `internal/modules/register.go`：查看当前真实注册模块；
5. `internal/modules/host|network|process|port|connection|service|package/module.go`：查看独立模块怎样把 Provider 事实转换为统一记录；
6. `internal/agent/scanner.go`、`invoke.go`：理解执行计划、只发布目标模块、依赖传递和故障隔离；
7. `internal/report/batch.go`：理解分片、摘要、manifest 最后写入和原子发布；
8. `internal/cli/run.go`、`scan_options.go`、`output.go`：理解动态命令和输出规则；
9. `cmd/asset-agent/runtime_linux.go`、`runtime_unsupported.go`：理解平台 Provider 注入。

## 3. 当前模块依赖图

```text
host ──┬── network
       ├── process ── port ── connection
       ├── service ──(软依赖)→ process
       └── package
```

- `network` 使用 host 的稳定主机 ID；
- `process` 使用 host 的 Boot ID；
- `port` 使用 process 事实调用一次 SocketProvider，并在 Internal 中保留全部 Socket；
- `connection` 只复用 port Internal，不再次扫描 Socket；
- `service` 硬依赖 host、软依赖 process，复用 cgroup 事实推导运行态（无真实 MainPID，不发布 runs_as）；
- `package` 读 dpkg/apk 文本数据库，稳定 ID 不含版本（host + arch + name）；
- 单模块扫描会执行必要依赖，但只发布目标模块记录；
- `all` 是 Registry 的虚拟目标，不存在名为 all 的模块或采集器。

## 4. 包职责

| 层 | 关键文件 | 职责 |
|---|---|---|
| 启动 | `cmd/asset-agent/main.go` | 初始化平台运行时并把参数交给 CLI。 |
| CLI | `internal/cli/run.go` | 通过 `Runtime.Modules` 动态生成模块命令，处理迁移别名。 |
| 编排 | `internal/agent/scanner.go` | 执行依赖计划，保留内部结果并决定哪些结果公开。 |
| 故障边界 | `internal/agent/invoke.go` | 每模块 timeout、panic 恢复和结构化错误。 |
| 模块注册 | `internal/module/registry.go` | 拒绝重复/未知依赖/环，生成分层确定性计划。 |
| 内置模块 | `internal/modules/*` | 生成平台无关资产、关系、状态和证据。 |
| Provider | `internal/provider/*` | 用能力名注册平台数据源；Linux 适配器只绑定采集函数。 |
| Linux 采集 | `internal/collect/*` | 读取受限 procfs/sysfs/标准库事实；不执行 Shell。 |
| 安全读取 | `internal/platform/files.go` | 将 Linux 绝对路径限制在可信根目录并限制读取大小。 |
| 脱敏 | `internal/security/redact.go` | 处理命令行中的密码、Token 和 URL 凭据。 |
| 协议 | `internal/model/batch.go` | 定义 2.0 内存批次和磁盘 manifest。 |
| 文件交付 | `internal/report/batch.go` | 流式 JSONL、SHA-256、权限、失败清理和原子目录发布。 |

## 5. 端口和连接事实链

```text
/proc/net/tcp*、udp*
  → collect/socket.ParseProcNet
  → Socket（端点、状态、inode）
/proc/<pid>/fd
  → collect/socket.Correlate
  → Socket.ProcessIDs / socket_process
  → port 模块：LISTEN 与本地 UDP → port + listens_on
  → connection 模块：ESTABLISHED → connection + connects_to
```

归属必须来自 inode/进程文件描述符证据，不根据端口号或进程名猜测。

## 6. 输出链

```text
Scanner.ScanTarget
  → model.Batch
  → report.WriteBatch
  → inbox/.partial-<scan-id>/
  → <module>-NNNNN.jsonl / relationships-NNNNN.jsonl
  → manifest.json（最后写入）
  → sync
  → inbox/<formal-batch>/（原子 rename）
```

CMDB 只能读取正式目录，并按 manifest 校验记录数、字节数与 SHA-256。`partial`、`failed`、`timeout` 和 `unsupported` 不能产生删除语义。

## 7. 测试定位

## 8. 当前阶段边界

当前注册表有 `host`、`network`、`process`、`port`、`connection`、`service`、`package`。资源、文件系统、磁盘、容器、文件、组件和应用扫描，以及常驻调度、事件、ack 和保留清理，均属于后续阶段；当前协议不会为这些未实现域输出伪空字段。
